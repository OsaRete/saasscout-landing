# Snapshot Canonical Contract

## Purpose

This document defines the canonical architectural contract of a Snapshot.

A Snapshot is the fundamental historical intelligence artifact of the SaaSScout Data Moat.

Its purpose is to preserve, in a deterministic and immutable way, the intelligence generated during a single Discovery execution.

This contract defines **what a Snapshot is**, **what it is not**, and the architectural rules that every future implementation must respect.

This document is implementation-independent.

It intentionally avoids database schemas, TypeScript interfaces, API contracts, or infrastructure details.

---

# Architectural Role

The Snapshot is the bridge between two worlds:

Stateless Intelligence

↓

State Accumulation

The Modular Intelligence Engine produces intelligence but has no memory.

The Data Moat accumulates intelligence over time but never performs intelligence generation.

The Snapshot is the immutable bridge connecting both.

Every successful Discovery produces exactly one Snapshot.

Snapshots become the historical input for all future accumulated intelligence.

---

# Goals

The Snapshot exists to:

- preserve the complete intelligence generated by one Discovery
- preserve historical context
- preserve evidence references
- preserve confidence metrics
- preserve engine versions
- preserve provenance
- enable future comparison between Discoveries
- enable Knowledge Evolution
- enable Memory
- enable Learning
- enable Recommendation
- enable Prediction

A Snapshot represents **what the platform knew at a specific moment in time**.

---

# Non-Goals

A Snapshot is NOT:

- a database schema
- an API response
- a cache
- a UI model
- a report
- an LLM conversation
- prompt history
- raw provider payload
- canonical knowledge
- a recommendation
- mutable state

Snapshots preserve intelligence.

They do not replace the Data Moat.

# Snapshot Characteristics

Every Snapshot must be:

## Immutable

After creation, the Snapshot can never change.

Corrections produce a new Snapshot.

Historical information must never be rewritten.

---

## Deterministic

Identical Discovery outputs must always generate identical Snapshots.

Snapshot creation must never depend on:

- timestamps (except creation metadata)
- randomness
- LLM generation
- provider ordering
- infrastructure

---

## Self-contained

A Snapshot must contain everything required to understand the Discovery outcome.

Future components should never need to reconstruct missing intelligence.

---

## Traceable

Every important conclusion preserved inside a Snapshot must be traceable back to supporting evidence.

Snapshots must never contain intelligence without provenance.

---

## Versioned

Every Snapshot must preserve:

- Snapshot Contract Version
- Engine Version
- Intelligence Version
- Confidence Version (future)
- Normalization Version (future)

Version history enables future reprocessing without rewriting history.

---

## Provider-independent

Snapshots must never expose provider-specific structures.

Examples:

OpenAI

Claude

Gemini

Reddit

X

SerpAPI

Product Hunt

GitHub

must all be normalized before Snapshot creation.

Changing providers must never require Snapshot redesign.

---

# Ownership

The Snapshot Engine owns:

- Snapshot construction
- normalization
- validation
- version assignment
- immutable Snapshot creation

The Snapshot Engine does NOT own:

- Discovery
- Knowledge Evolution
- Memory
- Learning
- Recommendation
- Prediction
- Data Moat querying
- Business decisions

---

# Relationship with the Data Moat

Snapshots are historical observations.

The Data Moat is accumulated intelligence.

The Data Moat is built from many Snapshots.

A Snapshot never becomes canonical knowledge by itself.

Knowledge Evolution determines what becomes accumulated knowledge.

---

# Relationship with Observations

A Snapshot may contain multiple future Observations.

Observation extraction occurs after Snapshot validation.

Observation extraction never modifies the Snapshot.

Snapshots remain immutable.

Observations are derived.

---

# Relationship with Knowledge

Knowledge is never directly persisted by Discovery.

Knowledge is always derived.

Discovery

↓

Snapshot

↓

Observations

↓

Knowledge

↓

Historical Intelligence

This separation prevents Discovery logic from contaminating accumulated intelligence.

# Architectural Invariants

The following invariants must never be violated.

## Invariant 1

Every successful Discovery produces exactly one Snapshot.

---

## Invariant 2

Snapshots are immutable.

---

## Invariant 3

Snapshots never become canonical knowledge directly.

---

## Invariant 4

Knowledge is derived from Snapshots, never generated directly by Discovery.

---

## Invariant 5

Snapshots never contain raw provider payloads.

---

## Invariant 6

Snapshots preserve evidence references, not provider implementations.

---

## Invariant 7

Snapshot generation is deterministic.

---

## Invariant 8

Snapshots never depend on AI provider formats.

---

## Invariant 9

Snapshots preserve historical truth.

Corrections create new Snapshots.

History is never rewritten.

---

## Invariant 10

Snapshot creation must never change production behavior.

---

## Invariant 11

Snapshot creation must never trigger Learning.

---

## Invariant 12

Snapshot creation must never modify recommendations.

---

## Invariant 13

Snapshot creation must never update the Data Moat directly.

Knowledge Evolution owns that responsibility.

---

## Invariant 14

Snapshots preserve intelligence.

They never interpret intelligence.

---

## Invariant 15

The Snapshot Contract is the single architectural source of truth for Snapshot structure.

Future implementations must conform to this contract rather than redefining Snapshot semantics in code.

---

# Future Compatibility

The Snapshot Contract is intentionally designed to support future capabilities without architectural redesign.

Future layers include:

- Knowledge Evolution
- Memory
- Learning
- Recommendation Engine
- Prediction Engine
- Founder Intelligence
- Validation Engine
- Multi-provider ingestion
- New AI models
- New intelligence engines

These systems consume Snapshots.

They never redefine them.

---

# Success Criteria

The Snapshot Contract is considered successful when:

- every Discovery can be represented by exactly one immutable Snapshot
- historical intelligence is preserved without ambiguity
- future engines can consume Snapshots without redesign
- Snapshot creation is deterministic
- providers remain replaceable
- production behavior remains unchanged
- accumulated intelligence remains independent from any single AI model

The Snapshot Contract is therefore the canonical architectural foundation of the Data Moat.
