# Disabled production authorization intent codec

B4.2-B2.9 implements only the first step of [B2.8](../../docs/V8_B42_B2_8_PRODUCTION_AUTHORIZATION_ISOLATION_ARCHITECTURE.md), section 4/7. No production callers. **Production owner withdrawal is disabled and NO-GO. A syntactically valid intent is not proof of independent owner consent.**

The architecture specifies field semantics in prose rather than an exact wire field list. This restricted v1 names them as follows, retaining the POC's applicable snake_case names without reusing its rotation overloads:

| Field                     | Wire representation / meaning                                                                              |
| ------------------------- | ---------------------------------------------------------------------------------------------------------- |
| `version`                 | Integer `1`; new production domain, distinct from POC                                                      |
| `audience`                | 1–128 ASCII `[A-Za-z0-9:._/-]`; exact deployment/project namespace, changed after restore                  |
| `owner_subject`           | Same restricted ASCII identifier; independently established external subject, never Auth/service authority |
| `owner_id`                | Lowercase UUID; exact mapped workspace owner UUID                                                          |
| `evidence_promotion_id`   | Lowercase UUID; exact promotion                                                                            |
| `operation`               | Only `withdraw`; spelling does not enable execution                                                        |
| `revision`                | Nonnegative safe integer; expected lifecycle revision                                                      |
| `registry_epoch`          | Nonnegative safe integer; protected registry epoch                                                         |
| `credential_id`           | Canonical unpadded base64url, 1–1024 decoded bytes; enrolled WebAuthn credential identifier                |
| `request_id`              | Lowercase UUID; request uniqueness key, not consumed here                                                  |
| `server_challenge`        | Canonical unpadded base64url, exactly 32 bytes; nonce generated by future protected service                |
| `issued_at`, `expires_at` | Nonnegative safe integer Unix seconds; issuance inclusive, expiration exclusive; lifetime 1–300 seconds    |
| `context_digest`          | 64 lowercase hex characters; SHA-256 digest of displayed immutable evidence context                        |

Canonical UTF-8 text is `SaaSScout:production-owner-authorization:v1\n` followed by compact JSON in the table's exact field order. All input values must have exact types; there is no coercion or Unicode normalization. Decode accepts only this representation, rejecting duplicates, reordered fields, whitespace, escaped alternatives and alternate number spellings. Object encoding accepts only exact own enumerable data properties and returns deterministic text. Limits are codec representations, not enrollment/authorization policy. The future context producer must define and test the displayed-context bytes; supplying a digest here does not prove correct display.

Both encoding and decoding require an explicitly supplied trusted clock. No implicit clock or skew allowance exists. Future monitored time/error policy is separate. `decodeBoundIntent` compares **every** field to independently supplied expected context, including nonce, subject mapping, audience, context and registry state. Request-derived expected values provide no protection. No module looks up or authenticates that context.

Results are frozen schema values only: no approval boolean, receipt, signature check, key possession, independent identity, replay protection or authority. An attacker can copy all fields and obtain the same decoded value. Service-role/internal-test claims never acquire authorization; extra authority/role/proof fields are rejected, while arbitrary syntactically valid external-subject labels cannot be authenticated by this codec. Offline substitution tests establish equality checks only, not actual IAM resistance or tamper authenticity. No credentials, network, SQL, migrations, enrollment/recovery, lifecycle changes, current reads, Knowledge Evolution or POC changes.
